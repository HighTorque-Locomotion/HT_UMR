# 新 XML 适配避坑：40V 拧臂问题复盘与验收清单

记录日期：2026-09-13。适用范围：本仓库的表面点对应重定向流程。
40V 修复基线：[cf581f5](https://github.com/HighTorque-Locomotion/UMR_HT/commit/cf581f58072f0e7ec32c169faf002473bcd07ca8)。

## 1. 核心结论

**外形上对应得像，不等于运动学上对应得正确。**

40V 的异常不是简单的手臂限位问题。自动生成的上臂、前臂对应点被绑定到相关关节上游的刚体，导致这些目标不能由预期关节满足；法向匹配项随后驱动肩部等其他关节代偿，出现拧臂。修改限位不会改变点的刚体归属。

适配新机器人时，必须同时验证三件事：点对应的语义、最终绑定的真实网格/刚体，以及该刚体是否受目标关节驱动。仅检查 T-pose 点云或能否输出视频不够。

## 2. 为什么自动匹配会犯这个错误？

### 第一步：学习两种外形上的点如何对应

当前训练通过模板点加残差重建目标点云。训练损失包括：

| 损失 | 作用 | 不能保证的事情 |
| --- | --- | --- |
| Chamfer 距离 | 拟合目标外形 | 人体前臂点属于机器人前臂 |
| 点间排斥 | 避免点过度聚集 | 点由正确关节驱动 |
| 残差正则 | 限制模板形变幅度 | 刚体层级正确 |
| 邻域边平滑 | 保持相邻点形变平滑 | 跨关节处的运动语义正确 |

这些损失没有明确规定“人体前臂点必须对应机器人肘关节下游的表面”，也没有显式加入目标关节影响或关节 Jacobian 的约束。

代码：[训练实现](../scripts/train_correspondence_template_residual_ae.py)，参见 `chamfer_l2`、`point_repulsion_loss`、`residual_regularization_loss`、`residual_edge_smoothness_loss` 及训练循环中的四项加权和。

本次 40V 使用 1024 slots / 20 epoch 演示配置。训练规模可能影响对应质量，但没有独立实验能证明仅增加点数或训练轮数即可消除这个错误。

### 第二步：把学到的机器人点贴到真实网格表面

原始绑定流程合并机器人可视网格，再寻找附近表面，依据命中的面决定点所属的 geom 和 body。它没有自动检查“这个刚体是否真的会随目标关节运动”。

因此，学到的前臂对应点如果落在大臂附近，就可能固定到大臂外壳上。空间上就近，并不代表动作含义正确。双臂伸直的 T-pose 中，大臂、小臂方向接近，问题不一定显眼；弯肘或扭臂后，两者运动不同，错误才暴露。

代码：[逐帧重定向实现](../scripts/retarget_smpl_to_humanoid_surface_vector.py) 的 `bind_robot_slots`。**当前修复版在配置了 `robot.surface_slot_body_bindings` 时增加语义约束；没有配置时仍保留原始绑定行为。训练损失本身未修改。**

## 3. 本次 40V 的直接证据

以下是旧版实际进入优化的 selected slots，而不是全部训练点：

| 人体语义段 | 旧版 40V 绑定情况 | 对目标关节的影响 |
| --- | --- | --- |
| 右上臂，15 点 | shoulder_pitch 2、shoulder_roll 11、torso 2 | upper_arm_joint 下游 0/15 |
| 左上臂，15 点 | shoulder_pitch 2、shoulder_roll 12、torso 1 | upper_arm_joint 下游 0/15 |
| 右前臂，8 点 | 全在 upper_arm_link | elbow_joint 下游 0/8 |
| 左前臂，8 点 | 全在 upper_arm_link | elbow_joint 下游 0/8 |

这些上臂/前臂法向目标对对应 upper_arm/elbow 关节的 Jacobian 列全部为零。这里是**刚体层级导致的结构性零值**，不能简单归因于某一帧的奇异姿态。手部目标仍能驱动肘部，因此也不能说整个求解器完全没有肘部观测；问题是不同目标相互冲突。

对 `aiming1_subject1` 第 870 帧（29 秒）和第 3240 帧（108 秒）的受控诊断发现：

- 保留旧绑定，迭代增加到 80 次，异常仍然存在。
- 用 ccrp 手臂姿态初始化，仍收敛回近似异常解。
- 关闭人体 self-contact map，异常仍然存在。
- 在原 XML、限位和目标权重下，仅调整上臂/前臂点的刚体归属，两个异常帧明显改善。

最初的因果实验保持 T-pose 世界位置/法向不变，把点虚拟绑定到下游刚体。**这种点可能不在真实表面上的做法只用于诊断，不是正式修复。**

Pro 的对应点也不完美，但保留了部分正确下游观测，因此没有出现同样的关键观测全丢失。不能据此认定 Pro 有专享优化，或认为名字、外观相近的 XML 可以直接复用对应关系。当前 GMR/ccrp 的显式 body/关键点映射不依赖这份 UMR 学习表面对应，故不共享这个具体错误。

原始诊断记录保留在本地 `output/arm_diagnosis_aiming1/`，包括 `README.md`、`40v/mapping.json`、`40v/joint_influence.json` 和单帧消融记录；正式绑定检查结果在 `output/dance1_five_panel/corrected_umr/binding_regression.json`。这些历史输出未随本文上传，本文保留了关键统计及其适用范围。

## 4. 已落实的修复与边界

[40V 默认配置](../demo_configs/umr_demo_piplus_s_40v.json) 指定：

```json
"surface_slot_body_bindings": {
  "leftArm": ["l_upper_arm_link"],
  "rightArm": ["r_upper_arm_link"],
  "leftForeArm": ["l_elbow_link"],
  "rightForeArm": ["r_elbow_link"],
  "leftHand": ["l_wrist_link"],
  "rightHand": ["r_wrist_link"]
}
```

该字段放在 `robot` 内。程序将对应语义段的点限制投影到指定 body 的**真实可视网格**，重新计算局部位置和表面法向，再构造后续运动目标。不能只改 body ID 而沿用错误的局部坐标/法向。

- 40V 默认配置及其派生配置已启用修复；原始轴向、几何和关节限位不变。
- 默认逐帧迭代 3 次、初始化 60 次；这是运行设置，不是根因修复的替代品。
- 逐帧与 batch 入口共享修正绑定逻辑。
- 修复后的逐帧结果 NPZ 保存 `semantic_binding_audit_json` 和 `retarget_config_json`，便于追踪配置。
- 语义映射是机器人特定适配。**不要把以上 body 名称机械复制到新 XML；必须核对新模型的实际运动学层级。**
- 若映射引起大幅投影位移，应回查 T-pose、坐标轴、尺度和训练对应质量，不能把语义重投影当作任意错误对应的万能修复。

完整运行命令及可选强自碰撞参数见 [40V 使用说明](../demo_configs/README_40V.md)。

## 5. 新 XML 适配检查清单

### A. 模型和配置

- [ ] 为新机器人创建独立配置、对应点缓存和输出目录；记录 XML/mesh、源动作、代码提交和有效配置版本。
- [ ] 核对自由度、joint/body 层级、轴向、单位、限位及 body 局部原点。不要凭名称判断哪个 body 是前臂。
- [ ] 核对 T-pose、人体到机器人坐标变换、左右对应及尺度。检查 visual geom 的真实所属 body。
- [ ] 配置覆盖的关节名称逐项匹配，避免拼写错误导致限位或姿态设置未生效。
- [ ] XML、网格、T-pose 或预处理改变后重新生成或验证对应缓存；仅改限位通常不能修正绑定归属。

### B. 表面绑定与运动学影响（必须在完整录制前完成）

- [ ] 按人体语义段统计“slot → geom → body → 祖先关节”，同时检查全部 slots 与实际 selected slots。
- [ ] 确认上臂、前臂、手部等关键段具有对应目标关节下游的有效观测；发现一整段位于上游立即停止调权重，先修绑定。
- [ ] 必要时配置 `robot.surface_slot_body_bindings`；确认 body 存在、具有可视网格，且源语义标签确实有点，避免空段被跳过。
- [ ] 验证投影点位于指定刚体的真实表面，局部位置/法向与参考姿态一致，法向为单位向量；检查投影位移异常值。
- [ ] 对目标关节施加小扰动，检查该段点的位置和法向是否按预期变化；可用有限差分核对 Jacobian。
- [ ] 至少在 T-pose 和弯肘/扭臂姿态下检查。单个点恰好在轴线上，或法向平行旋转轴，Jacobian 为零可能正常；**不能要求每个点、每个方向都非零，也不能将一整段的结构性零值忽略。**
- [ ] 检查观测方向的独立性；有非零 Jacobian 只是必要的局部检查，不代表所有自由度都被充分约束。

### C. 动作和全长验收

- [ ] 先用左右独立抬臂、弯肘、上臂扭转、交叉手和接近身体的动作检查，不能只看静态 T-pose。
- [ ] 与同一人体源逐帧对比肩—肘、肘—掌心的方向，左右分别统计。机器人末端 body 原点未必是掌心，应使用模型对应的局部偏移或 site。
- [ ] 固定根/躯干和目标定义做消融，再比较位置/法向残差；不要直接比较根轨迹不同的方法总损失。
- [ ] 检查关节限位饱和、相邻帧跳变、轨迹连续性、地面和机器人自穿透。位置残差和法向残差单位不同，不能仅按权重数值判断强弱。
- [ ] 跑完整 `aiming1_subject1` 与 `dance1_subject2`（或项目要求的完整回归集），验证帧数、FPS、有限值、单位四元数和有效限位，完整解码视频并抽查关键帧。
- [ ] 验收后再设为默认、归档失败配置；保留旧结果用于对照，不覆盖实验记录。

## 6. 已有自动检查能做什么、不能做什么

从仓库根目录，在已安装 UMR 依赖的环境中运行：

```bash
python scripts/check_surface_slot_body_bindings.py
```

[检查脚本](../scripts/check_surface_slot_body_bindings.py) 使用小型合成模型，无需 SMPL-X 权重或机器人资产。覆盖真实表面投影、关节影响、旧行为兼容、非法映射输入、两个入口一致性及 40V 默认配置继承。

**它不是任意新 XML 的自动验收器。** 新机器人的语义映射、真实层级、关键关节可观测性及完整动作质量，仍需执行上面的模型级检查。当前配置中的映射能防止已知 40V 错误再次默认出现，但不能保证新 XML 自动适配正确。

## 7. 自碰撞不能替代语义修复

人体 self-contact map 用于迁移接触关系；机器人 self-penetration 约束用于减少机器人碰撞几何穿透。两者都不能将绑定到上游的前臂点自动改绑到下游。

正确顺序是：**修正对应与绑定 → 验证运动学影响和动作 → 开启并验证碰撞约束**。强约束若允许 slack，仍可能残留穿透；碰撞几何也可能只是外观网格的近似。离线视频正常或数值检查通过不等于可直接安全上真机。
